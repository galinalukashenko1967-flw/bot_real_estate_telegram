# Ідеї для розвитку продукту

Записано після обговорення MVP, ринкового аналізу та перевірки доступності
API основних майданчиків нерухомості. Статус: **не реалізовано, для
опрацювання**.

## Контекст: що з'ясували про ринок

**Україна** — LUN.ua та OLX вже сильні гравці:
- OLX має офіційне [Partner API](https://developer.olx.ua/api/doc), але
  воно радше для публікації/керування власними оголошеннями, ніж для
  читання чужих
- DIM.ria має портал [developers.ria.com](https://developers.ria.com/) з
  довідниками (регіони/міста), публікаційного read-API для оголошень
  офіційно не знайдено
- LUN.ua публічного партнерського API не має, сам є агрегатором
  (об'єднує дублікати оголошень різних рієлторів через власний AI)
- Висновок: прямої "відкритої" мультиджерельної агрегації через офіційні
  API з коробки не вийде — потрібні або комерційні перемовини з кожним
  майданчиком, або технічний парсинг (юридичні/технічні ризики)

**Чорногорія** — ринок протилежний до українського:
- Немає централізованого MLS і немає домінантного агрегатора (як LUN в
  Україні)
- Кожна агенція веде свою базу окремо; основні майданчики: nekretnina.me,
  keynekretnine.me, estitor.com, renekretnina.me
- Жоден не має публічного API
- Це означає: покриття ринку потребує кількох парсерів (не менше, а
  більше, ніж в Україні) **або** прямих партнерств з невеликою кількістю
  агенцій (реальніше, бо гравців мало)
- Основна аудиторія — іноземні покупці (укр/рос/серб/європейці), часто з
  прицілом на ВНЖ через покупку нерухомості

## Ідеї для ринку України

Не намагатись конкурувати з LUN/OLX за агрегацію — закрити те, чого в них
немає:

1. ~~**Юридична перевірка об'єкта "із коробки"**~~ — **відхилено
   (2026-09-17).** Перевірено: пряма інтеграція з держреєстром неможлива,
   реалістичний шлях — тільки платна інтеграція з ліцензованим
   посередником (Опендатабот тощо), тобто чужий платний сервіс + залежність
   від зовнішнього API. Не наша компетенція, ускладнює бізнес-модель, не
   підходить.

2. **Голосові повідомлення на вхід** — AI транскрибує голосове і одразу
   витягує параметри запиту. Дрібна, але відчутна перевага для аудиторії,
   яка звикла писати голосом (особливо старше покоління).

3. **AI-оцінка вартості на основі власного датасету реакцій** — не
   "покажи оголошення", а "скільки насправді коштує моя квартира" —
   миттєва відповідь продавцю на основі внутрішньої бази + спарсених цін
   + **історії реакцій клієнтів на конкретні ціни** (це саме той сигнал,
   якого немає в публічних оголошеннях і немає у конкурентів — росте сам
   собою з кожним новим лідом).

4. **Рух далі по воронці, не тільки показ оголошення** — бот сам ініціює
   наступний крок (уточнює актуальність в продавця, готує чек-лист/
   документи для угоди), а не зупиняється на "показав варіант".

5. **Мультиканальність: Viber, не тільки Telegram** — частина аудиторії
   (40+) все ще звичніша до Viber. Архітектура вже дозволяє додати другий
   канал без переписування бізнес-логіки.

## Ідеї для ринку Чорногорії

Тут навпаки — реальне вікно стати першим агрегатором, бо домінантного
гравця немає:

1. **Мультиджерельний агрегатор** — зібрати 4-5 майданчиків
   (nekretnina.me, keynekretnine.me, estitor.com, renekretnina.me) в один
   пошук через AI-бота. Те, чого там фізично ні в кого немає.

2. **Багатомовний діалог (укр/рос/англ/чорногорська)** — основний попит
   іноземний, зараз це закривають тільки живі агенти-перекладачі. AI,
   що веде діалог кількома мовами — пряме влучання в біль.

3. **Фокус на 3-4 прибережних міста** (Будва, Котор, Тиват, Бар), а не
   всю країну — там концентрується попит іноземців.

4. **Партнерства замість парсингу** — гравців мало, реальніше
   домовитись напряму з кількома агенціями про фід даних, ніж з
   українськими гігантами.

## Контекст: Канада, Дубай, Данія (перевірено 2026-09-18)

**Канада** — на відміну від України, тут є **справжнє офіційне API**:
[REALTOR.ca DDF®](https://ddfapi-docs.realtor.ca/) від CREA, покриває ~65%
лістингів країни (тільки активні, без Квебеку/Манітоби/Ньюфаундленду).
Доступ дають членам CREA/бордів — тобто рієлтор з ліцензією є легальним
входом до цього API. Дублюється до нашої знайомої, що йде в рієлтори в
Канаді — вона потенційний легальний вхід. Діаспора: 1,3 млн етнічних
українців, стабільна, вкорінена (на відміну від тимчасових біженців) —
реально купує нерухомість, а не тільки орендує.

**Дубай (ОАЕ)** — ринок AI-чатботів для нерухомості вже **насичений**:
"AI chatbot isn't a competitive advantage anymore — it's becoming the
baseline". Десяток агенцій (PropPilot.ai, Korvax AI, BrandStory та ін.)
вже продають WhatsApp+AI боти. Офіційного API в Bayut/Property
Finder/Dubizzle немає, тільки сторонній scraping. Golden Visa (від AED 2
млн нерухомості = 10-річна резиденція) — потужний магніт для
рос./укр.-мовних інвесторів, які на відміну від місцевої більшості
звичніші до **Telegram, а не WhatsApp** — це та ніша, яку існуючі
WhatsApp-first вендори не закривають.

**Данія** — переглянуто: **не діаспорний/біженський ринок, а ринок
оренди для всіх**. Один з найнижчих рівнів володіння житлом в Європі
(1,4 млн орендних одиниць). Копенгаген — шалено конкурентний: оголошення
зникає за 7-30 днів, хто швидший — той і отримав квартиру/кімнату.
Додатковий головний біль: фільтри на кшталт "тільки для студентів"
ускладнюють пошук.

**Важливе уточнення (2026-09-18):** Boliga.dk — це сайт про **продаж**
нерухомості (ціни/оцінка), не оренду — вчорашнє припущення про нього як
орендний портал було помилкою. Найбільший орендний портал —
**BoligPortal**, і там контакт з власником **платний** (399 DKK/28 днів).
Але є безкоштовні альтернативи:
- **BoligZonen** — офіційно безкоштовний контакт з власником, без підписки
- **AkutBolig.dk** — позиціонує себе як найбільший безкоштовний орендний
  портал Данії (600+ власників)
- **Kvikbolig.dk** — безкоштовна реєстрація, 7 500 оголошень
- **Facebook-групи** ("Lejeboliger i Kbh" тощо) — жива, хаотична,
  повністю безкоштовна екосистема здачі житла напряму — оголошення
  зникають за хвилини, вручну стежити за десятком груп нереально
- **KKIK/CIU** (офіційні студентські гуртожитки) — безкоштовна
  реєстрація, але довжелезні черги (біль тут — час, не гроші)

## Ідея для ринку Данії — бот миттєвих сповіщень по оренді

**Статус: варто спробувати (рішення від 2026-09-18), конкурентів-AI не
знайдено.** Будувати на **BoligZonen + AkutBolig + Kvikbolig** (безкоштовні,
без ризику платного гейту), обходячи BoligPortal. Facebook-групи —
найцінніше джерело (найхаотичніше, найбільша реальна біль), але технічно
складніше (обмеження Facebook на автоматичний доступ до груп) — наступний
крок після базової версії, не стартова точка.

Не AI-діалог для кваліфікації покупця (як зараз для України), а **бот
моніторингу й миттєвих сповіщень** для орендарів:
- Клієнт задає критерії один раз (місто, ціна, кількість кімнат, чи
  згоден на кімнату в спільній квартирі, чи є обмеження типу "тільки
  студенти")
- Бот паралельно моніторить кілька майданчиків і **миттєво** пише в
  Telegram, щойно з'являється відповідне оголошення — швидкість тут
  головна цінність, бо ринок конкурентний
- Може одразу допомогти надіслати заявку/повідомлення власнику
  данською мовою (мовний бар'єр для іноземців)

Аудиторія ширша, ніж українці — будь-хто, хто орендує в Данії (студенти,
іноземці, місцеві). Монетизація: платна пріоритетність сповіщень для
орендаря, або комісія від власників/агенцій за швидких орендарів.

## Мінімум на завтра (рішення від 2026-09-18)

**Пріоритет #1:** замінити ручний ввід критеріїв пошуку текстом на
кнопкове меню вибору. Зараз клієнт має сам писати "хочу купити квартиру у
Києві, 2 кімнати, бюджет 90000" — натомість бот має показувати inline-меню
з варіантами для вибору одним натисканням:
- Тип угоди (купівля/оренда/продаж) — кнопки
- Місто (Київ/Львів) — кнопки
- Район — кнопки (список районів по обраному місту)
- Кількість кімнат — кнопки (1/2/3/4+)
- Ціна — кнопки з діапазонами (або повзунок кроками)

AI-діалог (вільний текст) залишається як альтернативний спосіб для тих,
хто хоче писати вручну — кнопки не замінюють його повністю, а
доповнюють як швидший шлях. Технічно: нові inline-клавіатури в
`app/bot/keyboards.py`, стан вибору через FSM (`aiogram.fsm`), запис у
той самий `Lead` через `app/services/qualification.py`.

**Пріоритет #2:** перевірити ситуацію з майданчиками нерухомості в
Чорногорії (контакти для партнерства, реальна складність парсингу),
перш ніж проектувати архітектуру багатомовного пошуку.
